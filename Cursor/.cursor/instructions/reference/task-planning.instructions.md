# Task Planning Instructions

## Purpose

Keep work split into implementable, reviewable units.

## Planning Rules

- one subtask should ideally produce one clear deliverable
- prefer <= 3 files per subtask when practical
- split when token estimate exceeds 15K
- assign owner tier and reviewer tier explicitly
- keep architecture work separate from pure implementation when possible

## Risk-Based Sequencing

- analysis before architecture before implementation
- boundary-risk work before low-risk boilerplate
- high-coupling changes before broad follow-up edits

## Definition of Done Planning

A task is not done until:
- intended change is complete
- validation story exists
- review path is clear
- open risks are surfaced honestly
