MayaCore MFE Context

Enterprise-grade multi-agent AI orchestration system. Claude Code, GitHub Copilot, OpenAI Codex ve Cursor için birleşik konfigürasyon framework'ü.

5-Tier Architecture 19 Security Hooks 20 Skills 4 Platforms xN Delegation 11 Agents

Genel Bakış

MayaCore MFE Context, yazılım geliştirme ekiplerinin AI agent'larını merkezi bir yapılandırma ile yönetmesini sağlayan bir framework'tür. Birden fazla AI platformunu (Claude, Copilot, Codex, Cursor) aynı mimari kalıplar, güvenlik kuralları ve iş akışları ile çalıştırır.

🏗️ Multi-Agent Orchestration

5 farklı yetkinlik seviyesinde agent'lar, tek bir orchestrator tarafından koordine edilir. Her agent kendi sorumluluk alanında çalışır.

🔒 Security-First Design

19 adet pre/post hook ile SQL injection, XSS, secret leak, path traversal gibi güvenlik açıkları otomatik engellenir.

📊 Self-Learning System

Agent'lar tekrarlayan kalıpları öğrenir, performans metriklerini takip eder ve oturum bazlı iyileştirmeler yapar.

⚡ Context Efficiency

Token bütçe yönetimi, progressive disclosure ve context-mode ile %40-60 token tasarrufu sağlanır.

xN Delegasyon Sistemi

Görevin karmaşıklığına göre birden fazla agent paralel veya sıralı olarak çalıştırılabilir. /x2 ile /x10 arası multiplier'lar kullanılır.

Multiplier T1 T2 T3 T4 T5 Toplam
/x2 0 1 1 0 0 2 agent
/x3 0 1 1 0 1 3 agent
/x5 1 1 1 1 1 5 agent
/x7 1 2 2 1 1 7 agent
/x10 1 2 3 2 2 10 agent

Örnek: /x5 Kullanımı

/x5 Bu microservice'i refactor et: authentication modülü

# Orchestrator şu şekilde dağıtım yapar:
# T1 (Principal)  → Mimari kararları al, review gate olarak bekle
# T2 (Staff Eng)  → Core authentication logic implementasyonu
# T3 (MidCoder)   → Boilerplate ve test yazımı
# T4 (Lead Anl.)  → Mevcut yapının analiz konsolidasyonu
# T5 (Analyst)    → Dependency araştırması ve güvenlik audit

Review Waves

xN delegasyonda review'lar wave bazlı yapılır:

  1. Wave 1: T5 çıktısını T4 review eder
  2. Wave 2: T3 çıktısını T2 review eder
  3. Wave 3: T2 çıktısını T1 final review yapar

Review Chain

Her kod değişikliği zorunlu review chain'den geçer. Üst tier, alt tier'ın çıktısını review eder.

T5 Output → T4 Review → T2 Output → T1 Final Review → ✅ Merge Ready T3 Output ↗

Context Mode

Context Mode, token bütçesini optimize eden ve gereksiz context yükünü azaltan bir çalışma modudur. Aktifleştirildiğinde agent'lar "query-first" prensibiyle çalışır.

Aktivasyon

/context-mode [görev açıklaması]

# veya doğal dil ile:
"Context-mode aktif olarak bu kodu analiz et"

Temel Prensipler

  1. Query-First: Önce "bu bilgi gerçekten gerekli mi?" sor
  2. Progressive Disclosure: Minimum bilgi ile başla, gerektiğinde derinleş
  3. Output Routing: Büyük output'ları context dışına yönlendir
  4. Budget Awareness: Her tier'ın token bütçesine uy

Token Bütçeleri

Tier Max Context Files Max Output Tokens PCD Depth
T1 15 32K Full
T2 12 24K Standard
T3 8 16K Focused
T4 10 12K Analysis-only
T5 6 8K Minimal

Engellenen Pattern'ler

❌ Context Mode'da Yasaklı
  • Dosya tam içeriğini output'a basma (summary kullan)
  • Tekrarlı bilgi gösterimi (reference ver)
  • Gereksiz açıklama paragrafları (bullet point kullan)
  • Network tool'ları explicit izinsiz (nc, curl, wget...)
Context Mode vs Normal Mode Karşılaştırması
MetrikNormalContext ModeTasarruf
Ortalama output/turn~2000 token~800 token%60
Context file yüklemeEager (tümü)Lazy (gerektiğinde)%40
Tekrarlı bilgiHer turn tekrarReference ile%50
Toplam session costBaseline-%45 average%45

Caveman Mode

Caveman Mode, output'u minimum token'a sıkıştıran "brutalist" bir çalışma modudur. Teknik doğruluğu korurken maksimum kısalık sağlar.

Aktivasyon

/caveman [görev]

# Seviyeleri:
/caveman          → Level 1 (Concise)
/caveman x2       → Level 2 (Terse)  
/caveman x3       → Level 3 (Ultra-minimal)

Kurallar

Kural Normal Caveman
Açıklama "Bu fonksiyon şu parametreleri alır ve şu değeri döner..." fn(x,y) → z
Onay "Değişiklikleri başarıyla uyguladım. İşte detaylar..." ✅ done
Hata "Bir hata oluştu. Detaylı açıklama..." ❌ TypeError L42
Plan Paragraflar halinde açıklama Bullet list, max 5 item

Ne Değişmez?

ℹ️ Caveman sadece output format'ını etkiler
  • Kod kalitesi aynı kalır (hooks çalışmaya devam eder)
  • Security kontrolleri aktif kalır
  • Review chain tetiklenir
  • Metrics kaydedilir

Örnek

# Normal mode output:
"Authentication modülündeki login fonksiyonunda bir bug tespit ettim. 
Kullanıcı null password gönderdiğinde NullPointerException fırlatılıyor. 
Sorunu çözmek için password null check ekledim ve uygun error response 
döndürdüm. İşte değişiklikler..."

# Caveman mode output:
"fix: null check @ AuthService.login:34 → 400 if !password"

Özel Hook Yazma

Hook Anatomisi

#!/usr/bin/env bash
set -euo pipefail

# stdin'den tool input JSON'ını oku
INPUT=$(cat)

# jq varsa kullan, yoksa grep fallback
if command -v jq >/dev/null 2&&1; then
  CONTENT=$(jq -r '.tool_input.content // empty' <<<"$INPUT")
else
  CONTENT=$(echo "$INPUT" | grep -o '"content"\s*:\s*"[^"]*"' | head -1 | sed 's/.*: *"//;s/"$//')
fi

# Kontrol mantığı
if echo "$CONTENT" | grep -qE "DANGEROUS_PATTERN"; then
  # BLOCK: exit 2 ile engelle
  echo '{"type":"text","text":"[my-hook] BLOCKED: reason"}' >&2
  exit 2
fi

# ADVISORY: exit 0 ile uyarı ver (engellemez)
if echo "$CONTENT" | grep -qE "SUSPICIOUS_PATTERN"; then
  echo '{"type":"text","text":"[my-hook] ADVISORY: warning message"}' >&2
fi

exit 0

Exit Codes

Code Anlam Davranış
0 Pass / Advisory İşlem devam eder, stderr uyarı olarak gösterilir
2 Block İşlem engellenir, agent'a hata mesajı döner

Sorun Giderme

Hook'lar çalışmıyor
  1. Hook dosyalarının executable olduğunu kontrol edin: chmod +x .claude/hooks/*.sh
  2. settings.json'da doğru path'in tanımlı olduğunu doğrulayın
  3. Hook'un stdin'den JSON okuduğundan emin olun
  4. jq yüklü değilse grep fallback'in çalıştığını test edin
Agent doğru tier'da çalışmıyor
  1. config/tier-definitions.md içindeki model mapping'i kontrol edin
  2. config/delegation-rules.md içindeki xN tablosunu doğrulayın
  3. Agent dosyasındaki model: field'ını kontrol edin
Context-mode guard yanlışlıkla engelliyor
  1. Guard sadece /context-mode aktifken çalışır
  2. Gerekli network erişimi için ctx_execute wrapper kullanın
  3. Sensitive path listesini context-mode-guard.sh içinde düzenleyebilirsiniz
Leaderboard güncellenmiyor
  1. flock komutunun sistemde mevcut olduğunu kontrol edin (macOS: brew install util-linux)
  2. .leaderboard.lock dosyasının kilitli kalmadığını doğrulayın
  3. Session'ın düzgün sonlandığından emin olun (SessionEnd hook tetiklenmeli)
Graphify stale uyarısı

/graphify rebuild komutu ile graph'ı yeniden oluşturun. Veya .graphify-stale marker dosyasını silin:

find . -name ".graphify-stale" -delete
/graphify . --local-only
Copilot agent'ları görünmüyor
  1. VS Code'da Copilot Chat panelini açın
  2. .github/agents/ dizininin projenin root'unda olduğunu doğrulayın
  3. Agent dosyasının .agent.md uzantılı olduğunu kontrol edin
  4. VS Code'u yeniden başlatın
